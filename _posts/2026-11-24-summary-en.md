### [Ladybird enters alpha with installable macOS and Linux builds](https://ladybird.org/posts/alpha/) ⭐️ 8.0/10

Ladybird, a from-scratch browser engine with its own HTML parser, CSS engine, layout, JavaScript, and WebAssembly implementations, released its first alpha, with downloadable builds for macOS and Linux. The project still relies on external libraries for text shaping \(HarfBuzz\), 2D graphics \(Skia\), video \(ffmpeg\), and SQLite. Its October 2026 newsletter reported gaining 75,650 web-platform-tests subtests to reach about 2.18 million and pass Safari, most of the gain coming from AI coding agents filling in missing functionality over roughly five days; it also described moving style and layout to a separate thread, a new JavaScript JIT, and a Cranelift-based WebAssembly engine with a 7x improvement on JetStream 3. The alpha is explicitly incomplete: some sites will not work and it will crash sometimes, with broken-site and crash reporting built into the browser.

hackernews · janvdberg · Nov 23, 16:13 · [Discussion](https://news.ycombinator.com/item?id=50614249)

**「What Ladybird is」** Ladybird began as a browser built on SerenityOS, Andreas Kling&\#x27;s from-scratch operating system project, and inherits a large amount of its code from there. It implements most core browser components itself — HTML parsing, CSS, layout, JavaScript, and WebAssembly — while relying on external libraries only for text shaping \(HarfBuzz\), 2D graphics \(Skia\), video \(ffmpeg\), and SQLite. The project also adopted Rust for parts of its LibJS engine earlier in 2026, a port described as assisted by AI coding agents.

**「Impact」** Early testers report broad compatibility, including WebAssembly-heavy tools such as an ffmpeg-based video compressor and a Pyodide REPL, but service workers remain incomplete: Datasette Lite fails with &quot;undefined is not a function \(evaluated from &\#x27;navigator.serviceWorker.startMessages&\#x27;\)&quot;, and the source carries a FIXME annotation for that service worker API. Users evaluating Ladybird should test workflows that depend on service workers and web workers, and expect crashes and occasionally jerky scrolling. Security testing is an explicit goal, so crash reports are opt-in and reviewable before sending.

**「Community discussion」** Commenters testing the alpha reported that most sites they tried rendered correctly, with one calling NoVNC snappier than in Firefox; the main complaint was slightly jerky page scrolling. Others questioned the tradeoff of replacing self-developed libraries with production-grade ones like SQLite and Skia, and argued Ladybird should prioritize anti-fingerprinting measures such as randomized JS values and granular permissions.

### [Zhipu Releases GLM-5.4 as Its First Loop Transformer](https://z.ai/blog/glm-5.4) ⭐️ 8.0/10

Zhipu AI \(Z.ai\) has released GLM-5.4, which it describes as its first model built on a loop transformer architecture: a group of weight-shared layers runs for multiple iterations, refining hidden states from the previous pass to give a deeper network without increasing parameter count. No open weights are available, and access is currently restricted. Simon Willison reports that GLM-5.4 could not be reached through OpenRouter or the regular Z.ai API plan and required a Coding Plan subscription, whose keys work with the same OpenAI-compatible Responses API at https://api.z.ai/api/v1. His informal SVG tests at low, high, and max effort produced recognizable but flawed pelican-on-a-bicycle output, roughly comparable in quality to GLM-5.3; no benchmark details were supplied, so performance claims remain unverified.

hackernews · foohis · Nov 23, 10:06 · [Discussion](https://news.ycombinator.com/item?id=50609685)

**「What a loop transformer is」** In a standard Transformer, each layer runs once per forward pass. A loop transformer instead runs a group of weight-shared layers for multiple iterations, refining hidden states from the prior pass and adding effective depth without raising parameter count. GLM-5.4 is Zhipu&\#x27;s first model built this way, and it follows Thinking Machines Lab&\#x27;s Inkling 2 Mini, announced November 20, which runs the model&\#x27;s middle layers three times for every token. GLM-5.4 is not yet available as open weights; it can currently be reached through Z.ai&\#x27;s Coding Plan subscription rather than the regular API plan, although the Coding Plan&\#x27;s API key works with the same OpenAI-compatible Responses API at https://api.z.ai/api/v1.

**「GLM-5.4 access currently routes through the Coding Plan」** Developers who want to try GLM-5.4 currently have to go through Z.ai&\#x27;s GLM Coding Plan rather than the regular API or OpenRouter; the Coding Plan issues OpenAI-compatible keys at \`https://api.z.ai/api/v1\` that reach the new model, and in Claude Code Z.ai documents a \`glm-5.4\[1m\]\` variant with a 1,000,000-token auto-compaction window. Independent benchmarks, an API price, and open weights are not yet available, so capability claims beyond Z.ai&\#x27;s own comparison to 2T–3T parameter models remain unverified.

**「Community Discussion」** Commenters praised Zhipu for publishing technical detail about the loop transformer, contrasting it with more closed Western labs, and one explained the design as a way to cut memory-bandwidth cost by moving each layer to the chip once and reusing it across iterations. Others reported that Chinese models&\#x27; long &quot;marathon thinking&quot; sessions make simple tasks slow and annoying, with some suspecting the extra deliberation helps them match frontier benchmarks.

### [Anthropic repository posts claimed VP ≠ VNP proof for all fields](https://github.com/anthropics/formal-math/tree/main/vp-vnp) ⭐️ 8.0/10

Anthropic&\#x27;s formal-math GitHub repository contains a paper claiming that VP ≠ VNP over every field. The supplied material is only a link to the paper PDF, so no abstract, proof strategy, or formal Lean verification is described. A commenter quotes the paper acknowledging that it has not analyzed how the result relates to relativization and algebrization, two standard barriers in complexity-theory separations. The claim has therefore not been shown here to be peer-reviewed or independently checked.

hackernews · mikeryan52 · Nov 23, 22:09 · [Discussion](https://news.ycombinator.com/item?id=50620102)

**「Background」** VP versus VNP is the algebraic analogue of P versus NP: Leslie Valiant posed the VP ≠ VNP question in 1979, and it has remained open since. The distinction matters because algebraic circuits must compute correctly over every field element and its extensions, not just Boolean 0 and 1 inputs, which is why a separation claim does not automatically settle P versus NP. The circulating item reportedly pairs the paper with a Lean 4 formal proof and names Claude as an author, but the supplied material provides no abstract, proof details, or independent verification.

**「Verification Gap for the Claim」** Because the paper explicitly states it has not analyzed how the result relates to relativization and algebrization, complexity researchers should treat the separation as unestablished until those standard barriers are addressed and the proof is independently checked. The absence of peer review or an abstract in the supplied material means the claim cannot yet be relied on for downstream work in complexity theory.

**「Community discussion」** Commenters framed the paper as an intermediate result toward P vs NP rather than a resolution of it, with one suggesting Anthropic is pursuing the &quot;Holy Grail&quot; in stages. Others debated the implications for human mathematical research, including a commenter who asked whether graduate students should abandon problem-solving if AI systems can soon produce such proofs, and another who noted the absence of relativization and algebrization analysis as a limitation.

### [Stalwart Claims Exchange Compatibility as Open-Source Alternative](https://stalw.art/blog/microsoft-exchange-replacement/) ⭐️ 7.0/10

Stalwart announced Exchange-compatible support, positioning its open-source mail server as a drop-in replacement for Microsoft Exchange. The claim covers protocol-level compatibility rather than full replication of Outlook&\#x27;s Exchange integration, and Stalwart&\#x27;s regular plans do not include GoBD-compliant archival required for German tax authorities. The announcement prompted substantial Hacker News debate over whether the framing understates the remaining dependencies on Microsoft clients and bundles.

hackernews · shaunpud · Nov 23, 22:32 · [Discussion](https://news.ycombinator.com/item?id=50620349)

**「Background」** Stalwart is an open-source mail and collaboration server written in Rust. Stalwart 1.2.0 adds MAPI over HTTP, Exchange Web Services, ActiveSync, and Autodiscover support, the protocols Exchange clients use to connect. That protocol support is what lets Stalwart present itself as an Exchange replacement rather than a separate mail system requiring client reconfiguration.

**「Archival and client-side gaps limit adoption」** For German organizations subject to GoBD, Exchange compatibility does not by itself satisfy the requirement to retain email unalterably and provide tax-auditor access for up to ten years; per the supplied comment, this archival capability is absent from Stalwart&\#x27;s regular plans and open-source variants, so those users would need a separate archival layer. Administrators must also account for Microsoft&\#x27;s new Outlook, which a commenter says syncs a copy of IMAP mail to Microsoft, potentially undercutting a server-only replacement in mixed-client environments.

**「Community pushback」** Commenters challenged the &quot;drop-in replacement&quot; framing, pointing to Outlook&\#x27;s Exchange integration and Microsoft&\#x27;s new Outlook client, which syncs IMAP mail copies to Microsoft, as practical barriers to substitution, while the Office 365 bundle makes replacement costly for existing organizations. A German commenter added that Stalwart lacks GoBD-compliant, tamper-proof email archival for up to 10 years, and another argued that expanding Microsoft protocol compatibility ultimately weakens the open email ecosystem.
